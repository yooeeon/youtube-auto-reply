## 1. 배경과 목표

### 1.1 미션
지정된 연애 관련 유튜브 영상의 **내용과 맥락에 맞는 댓글**을 달아, 댓글을 읽은 사람이 **'운명원'에서 연애 사주를 보고 싶어지도록** 한다.

### 1.2 제품 목표
| # | 목표 | 성공 지표 |
|---|---|---|
| G1 | 세 칸(불러오기 → 선택 → 댓글 달기)만으로 실제 게시까지 끝난다 | 시연에서 사람이 손대지 않고 게시·확인까지 성공 |
| G2 | 댓글이 그 영상에서만 나올 수 있는 내용이다 | 모든 댓글에 영상 속 장면·말 근거가 1개 이상 있고, 대시보드에 근거가 함께 보임 |
| G3 | 시청자처럼 자연스럽고, 운명원을 보고 싶게 만든다 | 규칙 검사 통과 + AI 심사 점수 기준 이상 |
| G4 | 운영 규칙을 코드로 강제한다 | 영상당 1개, 하루 상한, 기록이 UI를 우회해도 막힘(DB 제약) |
| G5 | 처음 보는 사람이 설명 없이 쓴다 | 번호 붙은 세 칸, 비활성 버튼에 이유 표시, 빈 상태 안내 |

### 1.3 비목표 (Non-goals)
- 웹 배포, 다중 사용자, 로그인 시스템 — **로컬 실행 전용**.
- 사람의 클릭 없이 대량 자동 게시(스케줄러·배치 게시) — 스팸 위험이 크고 요구사항에도 없음.
- 대댓글, 좋아요, 구독 등 댓글 외 행동.
- 쇼츠(Shorts) 영상 게시 — UI 구조가 달라 안정성이 떨어짐 (→ [DECISIONS D-07](DECISIONS.md)).

## 2. 사용자와 시나리오

**사용자**: 지원자 본인(운영자) 1명. 평가자는 시연 영상과 코드로 결과를 확인한다.

**핵심 시나리오 (Happy path)**
1. 운영자가 `python -m app` 실행 → 브라우저에 대시보드가 열린다.
2. ① **[영상 불러오기]** → 최신 연애 영상이 썸네일·제목·채널·올린 날짜로 뜬다.
3. ② 영상 하나를 클릭 → AI가 자막·인기 댓글을 읽고 **고민 한 줄**, **근거 장면**, **댓글 초안**을 보여준다.
4. ③ 프로필(자동 배정 또는 유튜브1~3) 확인 → **[댓글 달기]** → 크롬 프로필이 열리고, 한 글자씩 타이핑 → 게시 → 내 댓글 확인.
5. 대시보드에 `게시 완료 · 댓글 보기` 링크가 뜨고, 아래 기록에 한 줄이 추가된다.

## 3. 기능 요구사항

우선순위: **P0 = 필수(평가 직결)**, **P1 = 가점**, **P2 = 있으면 좋음**

### 3.1 ① 영상 불러오기

| ID | 요구사항 | 우선 |
|---|---|---|
| F1-1 | [영상 불러오기] 클릭 시 YouTube Data API로 최신 연애 영상 검색 (`order=date`, `regionCode=KR`, `relevanceLanguage=ko`, 최근 7일) | P0 |
| F1-2 | 목록 항목: **썸네일 · 제목 · 채널 · 올린 날짜**(상대시간 + 절대일자) + 조회수 | P0 |
| F1-3 | 댓글 불가 영상, 쇼츠(≤3분), 라이브(지난 방송 포함), 1시간 초과, 음악·스포츠·뉴스 등 카테고리, 타로·사주 등 경쟁 채널은 목록에서 제외. 최신 검색은 4분 이상 영상만 요청 | P0 |
| F1-4 | 이미 댓글을 단 영상은 목록에 `✓ 댓글 완료` 배지 표시(선택은 가능, 게시 불가) | P0 |
| F1-5 | **링크 직접 입력**: URL/ID 붙여넣기 → 목록 맨 위에 추가 | P1 |
| F1-6 | **뜨기 직전 찾기** 탭: '연애' 키워드, 최근 48시간, 조회수 1,000~5,000 & 시간당 조회수 ≥150 → 🔥 배지, **초안까지만** 생성 | P1 |
| F1-7 | 검색 키워드는 설정에서 변경 가능 (기본: 연애, 썸, 남자심리, 여자심리, 이별, 재회, 짝사랑) | P2 |
| F1-8 | API 키 없을 때 yt-dlp 대체 경로 | P2 |

### 3.2 ② 영상 선택 & 댓글 초안

| ID | 요구사항 | 우선 |
|---|---|---|
| F2-1 | 영상 선택 시 자막 수집: 한국어 수동 자막 → 한국어 자동 자막 → (없으면) 제목·설명 | P0 |
| F2-2 | 인기 댓글 상위 20개 수집 (`order=relevance`) | P0 |
| F2-3 | **1단계 분석**: 영상이 다루는 연애 고민을 **한 줄로 정리** + 근거 장면/발언 2~4개(인용 + 타임스탬프) | P0 |
| F2-4 | **2단계 생성**: 시청자 페르소나로 후보 댓글 3개 생성 (유도 방식을 서로 다르게) | P0 |
| F2-5 | **규칙 검사**: 글자수, 링크·해시태그 금지, '운명원' 1회 포함, 지어낸 이용 후기 금지, 근거 장면 언급, 과거 댓글과 유사도 | P0 |
| F2-6 | **AI 심사**: 후보별 맥락성·자연스러움·유도력 점수 → 최고점 1개를 초안으로 선택 | P0 |
| F2-7 | 화면 표시: 고민 한 줄, 근거 장면(타임스탬프), 초안, 글자수 카운터, 검사 배지(✓/✗), 페르소나·유도 방식 | P0 |
| F2-8 | 초안 직접 수정 가능 — 수정 시 규칙 검사 재실행, 통과해야 게시 가능 | P1 |
| F2-9 | **[다시 만들기]**: AI 키로 새 초안 즉석 생성 (다른 페르소나/유도 방식 강제) | P1 |
| F2-10 | 분석·초안은 캐시(SQLite)해 같은 영상 재선택 시 즉시 표시 | P1 |

### 3.3 ③ 댓글 달기

| ID | 요구사항 | 우선 |
|---|---|---|
| F3-1 | [댓글 달기] → Playwright `launch_persistent_context`로 지정 프로필 폴더를 **headed** 크롬으로 연다 | P0 |
| F3-2 | 영상 이동 → 댓글 창 열기 → **한 글자씩 타이핑**(사람 같은 랜덤 지연) → 게시 → **내 댓글이 보이는지 확인** | P0 |
| F3-3 | 진행 상태 실시간 표시: `프로필 여는 중 → 영상 여는 중 → 입력 중(n/N자) → 게시 중 → 확인 중 → 게시 완료 · 댓글 보기` | P0 |
| F3-4 | 실패 시 **이유(사람이 읽는 문장) + 화면 캡처** 저장 및 표시 | P0 |
| F3-5 | 유튜브 **한국어 UI**에서 동작 (`hl=ko` 강제 + 한국어 라벨 기반 셀렉터) | P0 |
| F3-6 | 프로필 유튜브1 필수 지원 | P0 |
| F3-7 | **프로필 선택**: 유튜브1~3 드롭다운 + **자동 배정**(오늘 게시가 가장 적은 프로필, 동률이면 순서대로) | P1 |
| F3-8 | 성공 시 '댓글 보기' 링크(`watch?v=…&lc=<commentId>`)와 성공 캡처 저장 | P1 |
| F3-9 | 프로필 상태 점검: 로그인 여부·채널 보유 여부를 대시보드 상단에 표시, [로그인 하기] 버튼으로 최초 로그인 | P1 |

### 3.4 운영 규칙 — 코드에서 강제 (P0)

| ID | 규칙 | 강제 방법 |
|---|---|---|
| R1 | **영상당 댓글 1개** (계정 무관) | DB 부분 유니크 인덱스(`video_id` where status in `posting`,`posted`) + 게시 전 재검사 |
| R2 | **한 영상에는 계정 하나만** | R1로 자동 충족 |
| R3 | **하루 게시 상한 (기본 10)** | KST 자정 기준, `posted`+`posting` 건수 ≥ 상한이면 거부. 슬롯 예약은 트랜잭션으로 원자 처리 |
| R4 | **기록**: 영상·프로필·댓글·성공/실패·시간 | 모든 시도를 `attempts` 테이블에 append-only 기록, 대시보드에 시간순 표시 |
| R5 | 동시 게시 금지 | 전역 게시 락 1개 (한 번에 한 브라우저) |
| R6 | 게시 간 최소 간격 (기본 60초) | 직전 성공 시각 기준 쿨다운, 버튼에 남은 시간 표시 |

규칙 위반 시 버튼은 비활성화되고 **이유를 문장으로** 보여준다. (예: "오늘 상한 10개를 모두 사용했어요. 내일 0시에 초기화돼요.")

### 3.5 설정

```yaml
# config.yaml
profiles:            # 내 컴퓨터의 크롬 프로필 (폴더 이름 = 표시 이름)
  - { name: 유튜브1, dir: ./chrome-profiles/youtube1 }
  - { name: 유튜브2, dir: ./chrome-profiles/youtube2 }
  - { name: 유튜브3, dir: ./chrome-profiles/youtube3 }

rising:  { keyword: 연애, hours: 48, min_views: 1000, max_views: 5000, min_views_per_hour: 150 }
typing:  { min_delay_ms: 70, max_delay_ms: 190 }

```
비밀값(`YOUTUBE_API_KEY`, `ANTHROPIC_API_KEY`)은 `.env`.

## 5. 비기능 요구사항
- **실행**: macOS, Python 3.12+, Google Chrome 설치. `make setup && make run` 두 줄로 실행.
- **안정성**: 셀렉터는 한국어 접근성 라벨 우선 + id 대체, 각 단계 타임아웃·재시도 1회.
- **관측성**: 모든 단계 로그 + 실패 캡처 `data/screenshots/`.
- **보안**: API 키는 `.env`, 크롬 프로필 폴더·DB·캡처는 `.gitignore`.
- **비용**: 영상 1개당 LLM 호출 2회(분석+생성/심사) 내외, YouTube API 할당량 1회 불러오기 ≈ 100~200 units.

## 7. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 구글이 자동화 브라우저 로그인을 차단 | 게시 불가 | 최초 로그인은 **자동화 없이** 같은 `--user-data-dir`로 일반 크롬을 띄워 수동 로그인 → 이후 Playwright가 재사용 |
| 유튜브 DOM 변경 | 게시 실패 | 셀렉터를 한 파일에 모으고 다단 대체, 실패 시 캡처로 빠른 수정 |
| 댓글이 스팸 필터로 숨겨짐(보류) | "확인" 실패 | 확인 단계에서 '내 댓글' 노출 확인, 미노출 시 `확인 실패(보류 의심)`로 구분 기록. 프로필별 간격·상한 유지 |
| 자막 API IP 차단 | 맥락 약화 | yt-dlp 자막 대체 → 그래도 없으면 제목·설명 + 인기 댓글로 생성하고 UI에 "자막 없음" 표시 |
| 계정에 유튜브 채널 없음 | 댓글창 대신 채널 생성 팝업 | 프로필 상태 점검에서 사전 감지 |
| LLM이 길이/금지 규칙 위반 | 품질 저하 | 규칙 검사 실패 시 사유를 넣어 자동 재생성(최대 2회) |
