# 평가 기준 ↔ 기능 ↔ 시연 증거 매핑

> 모든 기능은 "어느 평가 항목 점수를 지키는가"로 정당화한다. 시연 영상에서 **평가자가 눈으로 확인할 수 있는 증거**를 반드시 화면에 남긴다.

| 평가 항목 (배점) | 평가자가 보고 싶은 것 | 우리가 만드는 기능 | 시연 영상 속 증거 |
|---|---|---|---|
| **실제 게시 (25)** | 세 칸을 차례로 → 크롬 프로필 열림 → 한 글자씩 타이핑 → 게시 → 실제로 확인 | headed 크롬 + 글자별 지연 타이핑 + 확인 단계 + `lc=` 링크 | 대시보드와 크롬 창을 **나란히** 녹화. 타이핑이 보이게 지연 70~190ms. 게시 후 [댓글 보기] 클릭 → 새 탭에서 해당 댓글 하이라이트. 가능하면 **다른 브라우저(로그아웃 상태)** 에서 댓글 노출 확인 |
| **맥락 이해 (25)** | 영상 속 구체적 장면·말을 짚음, 그 영상에서만 나올 댓글, 영상마다 다름 | 분석 단계(고민 한 줄 + 타임스탬프 근거 장면) → 장면 인용 강제 → 고유성 심사 → 과거 댓글 유사도 검사 | 초안 옆 `📍 02:13 "…"` 근거 표시. 영상 3개 연속 시연해 댓글이 서로 다름을 보여 줌. 자막 출처(수동/자동/없음) 표시 |
| **운명원 유도 (20)** | 시청자처럼 자연스럽고, 읽으면 운명원 연애사주를 보고 싶어짐 | 페르소나 + 4가지 유도 방식 순환 + 지어낸 후기 금지 검사 + 유도력 심사 | 페르소나·유도 방식 칩, 심사 점수/사유. 금지 규칙 배지 ✓ |
| **운영 규칙 (15)** | 영상당 1개, 하루 상한, 기록 | DB 유니크 인덱스, KST 일 상한, 쿨다운, append-only 기록 | ① 이미 단 영상에서 [댓글 달기] 비활성 + 이유 ② 상한을 2로 낮춘 설정으로 3번째 시도 거부 장면 ③ 하단 기록 타임라인(성공·실패 섞여서) |
| **사용성 (10)** | 설명 없이 세 칸 사용 | 번호 단계, 빈 상태 안내, 비활성 이유, 스테퍼, 사람 말 오류 | 시연 내레이션 없이도 화면 문구만으로 흐름 이해 가능 |
| **제작 의도 (5)** | 왜 이렇게 설계했나 | [DECISIONS.md](DECISIONS.md), README "설계 이유" 섹션 | 시연 마지막 30초: 설계 이유 3가지 요약 |
| **가점** | 프로필 1~3/자동 배정, 링크 입력, 즉석 재생성, 뜨기 직전 | F1-5, F1-6, F2-9, F3-7 | 각 기능 10~15초씩 시연 |

## 감점 위험 체크리스트 (시연 전 점검)
- [ ] 댓글에 링크·해시태그·타임스탬프 없음
- [ ] "운명원 가봤는데 / 봤는데 소름" 같은 후기형 문장 없음
- [ ] 같은 문장 시작("헐", "와 진짜")이 연속되지 않음
- [ ] 한국어 유튜브 UI에서 녹화
- [ ] 크롬 창이 **실제로 열리고 타이핑이 보이는** 장면이 잘리지 않음
- [ ] 게시 후 댓글이 보이는 장면 포함
- [ ] 실패 사례 1건(예: 댓글 꺼진 영상)과 캡처 표시 장면 포함 → 실패 처리 능력 증명
- [ ] 한 영상에 두 번 달기 시도 → 막히는 장면 포함
