### D-01 스택
- **이유**: 자막 추출(youtube-transcript-api)·yt-dlp가 Python 생태계에 있고, Playwright Python의 `launch_persistent_context`가 요구사항과 정확히 일치. 프론트 빌드 도구를 없애 "clone → 실행" 마찰 최소화.
- **대안**: Node/Next.js — UI 확장성은 좋지만 자막 라이브러리 안정성이 낮고 설치 단계가 늘어남.

### D-02 YouTube Data API
- **이유**: 썸네일·채널·올린 날짜·조회수·인기 댓글을 정확하고 빠르게 받음. '뜨기 직전' 계산에 정확한 조회수와 게시 시각이 필수. 시연 중 스크래핑 차단 위험 제거.
- **대안**: yt-dlp 전용 — 키가 필요 없지만 느리고 차단·구조 변경에 취약 → 대체 경로로만 사용.

### D-03 길이 해석
- **맥락**: 요구사항은 "40~120자"인데, 과제 예시 댓글은 공백 포함 139자/제외 104자. 즉 출제자는 공백 제외로 셌을 가능성이 있음.
- **제안**: 두 해석을 **동시에** 만족하는 구간(공백 제외 ≥40, 공백 포함 ≤120)만 허용 → 평가자가 어떤 방식으로 세도 통과. 대시보드 카운터는 두 값을 모두 표시.
- **대안**: 공백 제외만 적용 — 표현 여유는 늘지만 공백 포함으로 세는 평가자에게 감점 위험.

### D-04 4단계 파이프라인
- **이유**: 평가의 45%(맥락 25 + 유도 20)가 댓글 품질. LLM 한 번 호출은 길이·금지어 위반과 일반론 댓글이 섞여 나옴. 결정적 규칙은 **코드로**, 주관적 품질은 **심사 모델로** 분리해 둘 다 보장. 근거 장면을 먼저 뽑아 "그 영상에서만 나올 댓글"을 구조적으로 강제.

### D-05 Claude
- **이유**: 한국어 구어체·커뮤니티 말투 재현력, 구조화 출력(JSON 스키마)으로 고민 한 줄/장면/후보/점수를 안정적으로 받음.

### D-06 전용 프로필 폴더
- **이유**: 크롬은 기본 프로필 자동 제어를 막음(요구사항 명시). 구글은 자동화 브라우저 로그인을 차단할 수 있어 **로그인만 수동, 이후 자동화가 재사용**하는 구조가 가장 안정적.

### D-07 제외 대상
- **제안**: 쇼츠(≤60초)는 댓글 UI가 패널형이라 셀렉터가 다르고 실패율이 높음 → 제외. 라이브/예정, 댓글 꺼짐 영상도 제외.
- **논의**: 연애 콘텐츠는 쇼츠 비중이 크다. 시간이 남으면 쇼츠 지원(P2)을 추가할지?

### D-08 상한 카운트
- **제안**: 실제로 게시됐을 수 있는 건(`posting`, `posted`, `unverified`)만 상한에 포함. 게시 전 실패(로그인 안 됨 등)는 기록엔 남기되 상한은 소모하지 않음.

### D-09 최소 간격
- **제안**: 60초. 짧은 간격의 연속 댓글은 스팸 필터에 걸려 '확인' 단계 실패 위험. 시연에선 설정으로 낮출 수 있음.

### D-10 수동 트리거
- **제안**: 요구사항이 "[댓글 달기]를 누르면"이므로 사람 클릭만 게시를 시작. '뜨기 직전'도 "초안까지만"을 지킴.

### D-11 타임스탬프 금지
- **이유**: 유튜브는 댓글 속 `2:13`을 클릭 가능한 링크로 바꿈 → "링크 금지"에 걸린다고 볼 여지. 장면은 **말/상황 묘사**로 언급하고, 타임스탬프는 대시보드 근거 표시에만 사용.

### D-12 유도 표현 범위
- **허용**: 소문("잘 본다던데"), 본인 의향("보고 싶다/보러 갈까"), 질문("본 분 계세요?").
- **금지**: 본인 이용 후기, 지인 이용 후기("친구가 봤는데 맞았대") — 지인 후기도 지어낸 후기로 볼 수 있음.

### D-13 제출 후 실패
- **이유**: 제출 버튼을 누른 뒤 재시도하면 중복 게시 위험 → "영상당 1개" 규칙 위반. 확인 실패는 `unverified`로 남기고 운영자가 판단.

### D-14 조언자 페르소나 (2026-11-17)
- **맥락**: v0.1 초안("공감 → 운명원 잘 본다던데 나도 보고 싶다")은 광고 티가 나고, 장면과 운명원 사이 논리가 비어 있다는 피드백.
- **결정**: 화자는 영상 속 문제를 진단하고 해결 방법을 알려 주는 조언자. 운명원은 '연애 사주로 유명한 곳'이라는 평판으로만 소개해, 운명원이 이 고민의 해결책이라는 **정보**가 되게 한다.
- **기각한 대안**: 운명원 헤비 유저·팬 페르소나 — 과제의 "운명원을 직접 이용해 본 것처럼 지어낸 후기" 금지 규칙에 정면으로 걸리고, 읽는 사람을 속이는 글이 되므로 제외.

### D-15 AI 호출 방식 (2026-11-17)
- **맥락**: Anthropic API는 Claude 구독과 결제가 따로라 크레딧 충전이 필요.
- **결정**: `llm.backend: auto` — `ANTHROPIC_API_KEY`가 있으면 API, 없으면 이 컴퓨터에 로그인된 Claude Code CLI(`claude -p`)를 호출해 구독 사용량으로 처리. 둘 다 JSON 스키마 구조화 출력.
- **최적화**: CLI는 `--system-prompt`로 기본 지시문을 대체하고 도구·MCP·설정·세션 저장을 꺼서 호출당 ~1.5k 토큰, 2~25초.
- **한계**: 구독 방식은 본인 컴퓨터·본인 계정 전용. 코드를 다른 사람이 실행할 땐 API 키 방식을 쓴다.

### D-16 운명원 표현 (2026-11-17)
- **맥락**: "운명원이 그쪽으로 유명해요", "잘 본다고 소문났어요"처럼 확인되지 않은 평판을 사실로 단정해 작위적이라는 피드백.
- **결정**: "잘 본대요", "괜찮대요", "좋대요", "잘 본다던데"처럼 전해 들은 주관적·긍정 표현을 쓴다. 과제 예시 댓글의 "운명원 연애사주가 그렇게 잘 본다던데"와도 같은 결.
- **강제**: `validate.py`의 '단정 평판 없음' 검사(유명·소문났/난·이름난·정평·알려져 있·명성)로 걸러 내고, 심사의 자연스러움 항목에서도 감점.
- **유지**: 본인·지인 이용 경험(봤는데/다녀왔/친구가 봤 등)은 여전히 금지 (D-12).
